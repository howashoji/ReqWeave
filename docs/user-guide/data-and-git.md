# プロジェクトデータと git の併用

> 本システムのプロジェクトデータを**利用者自身が git で管理してよいか**についての指針。
> 本システムが同期のために内部で git を使うこととは別の話である。

## 1. まず知っておくこと

プロジェクトデータは**1 プロジェクト = 1 フォルダ**で、利用者端末のローカルディスクに置かれる。

- **共同プロジェクト**（同期先を設定したプロジェクト）のフォルダは**本システムが同期に使っている領域そのもの**である。
- **単独利用のプロジェクト**（同期先を設定していないプロジェクト）は本システムが同期の領域を作らない。

この違いによって、利用者自身が git を使ってよいかどうかが変わる。

## 2. 共同プロジェクトのフォルダでは、git のコマンドを実行しないでください

**してはいけないこと**: 共同プロジェクトのフォルダで `git commit` / `git checkout` / `git branch` /
`git reset` / `git gc` などを自分で実行すること。GUI の git クライアントでフォルダを開いて操作することも同じ。

**理由**: そのフォルダは本システムが取り込み・反映のために管理している領域である。
本システムは同期の状態を自分で作った目印で管理しているため、外から履歴や作業状態を書き換えると、

- 取り込み・反映が失敗する
- 他のメンバーの変更を取り込めなくなる
- 自分の変更が同期先へ載らなくなる

といったことが起こりうる。本システムの画面には git の言葉は出てこない。
フォルダの中に見慣れた作りを見つけても、
**本システムの持ち物として触らずにおく**のが安全である。

**バックアップや履歴が目的なら、本システムの機能で足りる**:

| やりたいこと | 使う機能 |
|---|---|
| 直前の状態へ戻したい | 自動退避（プロジェクトを閉じるたびに取り、10 世代まで残る） |
| 手元に控えを取りたい・別の端末へ移したい | 手動バックアップ（単一ファイルへの出力と、そこからの復元） |
| 誰がいつ何を変えたか見たい | 変更履歴・同期の記録 |
| 過去の版の成果物を見たい | 確定版は全世代が残る |

## 3. 単独利用のプロジェクトを自分で git 管理する場合

同期先を設定していないプロジェクトなら、フォルダを自分の git リポジトリとして管理してもよい。
本システムはそれを検知も阻害もしない。次の 2 点だけ守ること。

### 3.1 コミットは「プロジェクトを閉じた後」に行う

本システムは書き込みの途中で電源が落ちてもデータが壊れないように、**一時ファイルへ書いてから置き換える**
方式をとっている。
**プロジェクトを開いたままコミットすると、書き換えの途中の状態を記録してしまうことがある**
（複数のファイルにまたがる更新の一部だけが入った状態）。

必ず**プロジェクトを閉じてから**コミットする。自動でコミットする仕組み（保存のたびに実行する類）は使わない。

### 3.2 次のものはリポジトリに含めない

プロジェクトフォルダの直下に `.gitignore` を置き、次を除外する。

```gitignore
# 同じ端末で同じプロジェクトを二重に開いたときの保護に使う一時ファイル。
# 実行中だけ存在し、記録する意味がない（ReqWeave も同期・バックアップから除外している）。
locks/

# 質問票の返送ファイルを復号するための鍵。
# リポジトリへ置くと、返送ファイルの保護が意味をなさなくなる。
exchange-keys.yaml
```

- `imports/` の下にある原本ファイル（取り込んだ PDF・Word・Excel・PowerPoint）は、**変更しなくても容量を占める**。
  資料が多いプロジェクトではリポジトリが大きくなることを見込んでおく
  （プロジェクトあたりの総量の目安は 500MB。超えると警告が出るが、操作は止まらない）。
- `audit/`（AI 送信記録・変更履歴・同期の記録）は含めてよい。記録の追記だけなので履歴も読みやすい。

## 4. 成果物だけを git に置く運用

開発 AI へ渡すためにエクスポートした成果物を、
**出力先で** git 管理することは妨げない。エクスポートはプロジェクトフォルダの外へ書き出す操作であり、
本システムの動作に影響しない。この場合、上の 2 章・3 章の制限はかからない。

## 5. まとめ

| プロジェクトの種類 | 利用者自身の git 操作 |
|---|---|
| 共同プロジェクト（同期先あり） | **行わない** |
| 単独利用のプロジェクト（同期先なし） | 行ってよい。**閉じてからコミット**し、`locks/` と `exchange-keys.yaml` を除外する |
| エクスポートした成果物の出力先 | 自由 |
