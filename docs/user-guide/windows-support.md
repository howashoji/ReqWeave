# Windows で導入できる条件

> Windows 版は**コード署名を行わない**方針である。
> 署名しなくても標準ユーザー自身が導入できることを実機で確認したうえでの判断だが、
> **端末のセキュリティ設定によっては導入できない**。本書はその条件を書く。
> 初回起動の操作手順そのものは配布物に同梱の `初回起動の手順.md` にある。

## 1. 導入できる端末（確認済み）

管理者権限なしで導入・起動できることを実機で確認した環境:

| 項目 | 値 |
|---|---|
| OS | Windows 11 |
| Smart App Control | **オフ** |
| SmartScreen のポリシー | 既定 |
| 利用者 | **管理者権限を持たない標準ユーザー** |

この条件では次のとおり**標準ユーザー自身の操作だけで導入・起動できた**。

- 共有フォルダ（ダウンロード由来のマークが付かない経路）から受け取った場合: **警告なしに起動**。
- Web からのダウンロード（マークが付く経路）: SmartScreen の警告が出るが、
  **「詳細情報」→「実行」で起動でき、管理者のユーザー名・パスワードは求められない**。

## 2. 導入できない端末（利用組織が事前に確認すること）

次のいずれかに当てはまる端末では**配布経路を工夫しても導入できない**。

| 条件 | 何が起きるか |
|---|---|
| **Smart App Control が有効**（オン / 評価中） | 署名のない実行ファイルが**回避手段なくブロック**される。しかもこの検査は「インターネット由来のファイル」に限らず**すべての実行ファイル**に及ぶため、共有フォルダや USB で渡しても回避できない |
| **SmartScreen のポリシーが「ブロック」**（`ShellSmartScreenLevel` = Block） | 警告に「実行」のボタンが出ない。利用者が自分で通せない |

**確認方法**: Windows セキュリティ →「アプリとブラウザーの制御」→「スマート アプリ コントロール」の状態を見る。
ポリシーは情報システム部門の管理設定（グループポリシー / Intune）に依存するため、
**導入前に管理者へ確認する**こと。

該当する端末では現時点で本システムを導入できない。将来これらの端末でも警告なしに導入する必要が出た場合、
**Microsoft Store（MSIX）配布が唯一の手段**になる（現時点ではストア配布を採らず、自前で配布している）。

## 3. macOS との違い

同じ「管理者権限なしで導入できること」という要件でも、**成否が OS で分かれる**。

| | macOS | Windows |
|---|---|---|
| 署名 | **Developer ID 署名 + Apple の公証を行う** | **行わない** |
| ダウンロード由来のマークが付いた場合の初回起動 | 確認ダイアログで「開く」を押す。管理者の資格情報は不要 | SmartScreen の警告 →「詳細情報」→「実行」。管理者の資格情報は不要 |
| 端末の設定で導入できなくなる条件 | （署名・公証済みのため通常は無い） | Smart App Control が有効 / SmartScreen ポリシーがブロック |

macOS 側で署名と公証を導入したのは、**署名なしでは標準ユーザーが初回起動できず**
（システム設定からの許可に管理者の資格情報を要求される）、必須要件が成立しなかったため。
Windows は標準ユーザー自身で通せたため署名を見送っている。
