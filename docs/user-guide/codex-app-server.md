# Codex App Server を使う（ChatGPT のアカウントでも使える AIプロバイダ）

> 本システムは AIプロバイダとして **Anthropic / OpenAI / Google の各 API** に加えて、
> **OpenAI の Codex App Server** を選べる。Codex App Server は、本システムが
> **配布物に同梱した Codex を自分の端末で子プロセスとして動かし**、そこを通して AI を呼び出す接続口である。
> 本書は**利用者と利用組織が何をするか**を書く。

**Codex App Server を選んでも、Codex にコマンドを実行させたり、ファイルを作らせたり書き換えさせたりはしない**
（道具を使わせない設定で起動する）。使うのは応答の生成だけである。

## 1. 選べる端末（macOS 版だけ）

| OS | 設定画面のプロバイダ一覧での見え方 |
|---|---|
| **macOS** | 「Codex App Server」が**選択肢に出る** |
| **Windows** | **選択肢に出ない**（Anthropic / OpenAI / Google の 3 つだけが出る） |

Windows 版で選べるようにするのは**Windows の実機で動作を確かめた後**である。

> **未決（誰が・何を決めるか）**: Windows 版での提供時期は決まっていない。
> Windows の実機での検証の結果を見て、開発側が提供の可否と時期を決める。
> それまで Windows の担当者は従来どおり Anthropic / OpenAI / Google のいずれかを使う。

同じプロジェクトを macOS の担当者と Windows の担当者で分担してもよい。
AIプロバイダの設定は**端末ごと**であり、プロジェクトのデータには影響しない。

## 2. 認証方式は 2 つ（どちらか一方を選ぶ）

Codex App Server を選んだときだけ、認証方式の選択が画面に出る（他のプロバイダでは出ない）。

| 認証方式 | 何で払うか | 学習利用（既定） |
|---|---|---|
| **シークレットキー方式** | OpenAI の API の従量課金 | **学習に使われない** |
| **ChatGPT のアカウントでのサインイン** | 自分の ChatGPT のプランの利用枠 | **個人向けプランでは使われうる**（→ 3 章で止める） |

- キーの登録・保管は他のプロバイダと同じ（OS のセキュアストレージにのみ保管し、平文で再表示しない）。
- **どちらの方式でもキー・認証情報は担当者ごと・端末ごと**である。1 つのキーやアカウントをチームで共用する運用は想定していない。

### 2.1 ChatGPT のアカウントでサインインする手順

設定画面（またははじめの設定）で「Codex App Server」→「ChatGPT のアカウントでのサインイン」を選ぶと、
次の 4 つの状態を順にたどる。

| # | 画面 | 利用者がすること |
|---|---|---|
| 1 | **説明** | Codex が送信に付け足す内容（→ 5 章）・Codex の動作ログに残る呼び出し先の応答のクッキー（→ 5 章）・この認証方式に適用されるデータ利用ポリシーの参照先が示される。読んだうえで「サインイン」を押す |
| 2 | **待機** | **既定のブラウザで OpenAI のサインインのページが開く**ので、そこでサインインして許可する。本システムは**最大 15 分**待つ。待っている間も本システムの他の画面は使える。「ブラウザをもう一度開く」「取り消す」を押せる |
| 3 | **成功** | アカウント（メールアドレス）とプランが表示される。**個人向けプランのとき（プランを取得できなかったときを含む）は、学習に使われうることと停止方法が併せて表示される**（→ 3 章） |
| 4 | **失敗** | 原因と次に取る操作が日本語 1 文で示される。**設定は変わらない**（元の設定のまま使い続けられる） |

- 15 分の間に許可しなかったときは 4（失敗）になる。［もう一度サインイン］を押せばやり直せる。
- サインインで得た認証情報は **Codex が OS のセキュアストレージへ保管する**。本システムはその中身を読み出さない。
  macOS ではキーチェーンアクセス（または `security find-generic-password`）で、Codex が登録したエントリとして確認できる。
- **メールアドレスは画面に表示するだけ**で、アプリ設定・プロジェクトデータ・動作ログには保存しない。

### 2.2 サインアウトする

設定画面から確認操作を経てサインアウトする。サインアウトすると
**Codex のエントリが OS のセキュアストレージから消える**。

- サインアウト後は「未サインイン」になり、AI を呼ぶ操作は「キー未登録」と同じ扱いで止まる。
  参照・エクスポート等、AI を呼ばない操作は使える。
- 認証方式をシークレットキー方式へ切り替えるだけならサインアウトは要らない。
  **Codex が保管している認証情報を消したいときは、切り替えとは別にサインアウトする**。

## 3. 学習に使われないようにする（個人向けプランでサインインする場合）

**ChatGPT の個人向けプラン**（Free / Go / Plus / Pro 等）のアカウントでサインインして使う場合、
送信した対話とプロジェクトの文脈が **OpenAI のモデルの学習に使われうる**
（2026-09-14 に OpenAI ヘルプセンターの記事「How your data is used to improve model performance」の本文で確認）。

**止める方法は次の 2 つで、どちらか一方を行えば足りる**（両方行う必要はない）。

| # | 場所 | 操作 |
|---|---|---|
| 1 | **ChatGPT の設定「データコントロール」** | 「Improve the model for everyone」を**オフ**にする |
| 2 | **OpenAI のプライバシーポータル** | 「Do not train on my content」を選ぶ |

- **法人向けプラン（ChatGPT Business / Enterprise 等）と、シークレットキー方式（API）は既定で学習に使われない**。
  この場合は上の操作は要らない。
- 本システムはサインインの完了時と、はじめの設定・プロバイダ変更時の注意喚起で、この停止方法を表示する。
  **停止の操作そのものは ChatGPT 側で利用者が行う**（本システムからは変更できない）。
- 機密業務情報を外部の AI へ送ることが組織のポリシーに適合するかの判断は、
  従来どおり**利用組織側の責務**である。

## 4. 組織で使うなら（どの方式を案内するか）

**業務のプロジェクトで使う場合は次のどちらかを使う**。

| 使い方 | 案内 |
|---|---|
| **法人向けプラン（Business / Enterprise 等）のアカウントでサインイン** | 可。既定で学習に使われない |
| **シークレットキー方式** | 可。既定で学習に使われない。費用は OpenAI の API の従量課金 |
| 個人向けプランのアカウントでサインイン | **3 章の停止操作を行ったうえで、利用組織の判断で使う**。組織が管理しないアカウントを経由した送信になる |

**費用の集約は認証方式で変わる**。
シークレットキー方式では組織のキーへ費用が集まるが、
**ChatGPT のアカウントでのサインインでは費用が各担当者の ChatGPT のプランに付く**。
トークン消費の記録とプロジェクト単位のトークン上限はどちらの方式でも同じように働く。

## 5. Codex が送信に付け足すもの（開示）

本システムが Codex へ渡す内容のほかに**Codex 自身が次を送信に付け足す**。
除く設定が見つかっていないため**そのまま使うことを選んだうえで開示する**。

| 付け足されるもの | 中身 |
|---|---|
| **道具の定義文（4 種）** | `update_plan` / `request_user_input` / `apply_patch` / `view_image` の定型文。**Codex 固定の文言**で、利用者・端末・プロジェクトの情報を含まない。定義が送られるだけで、**道具は使わせない** |
| **User-Agent の OS の版と CPU の種類** | 例: macOS の版と、Apple Silicon か Intel かの区別 |
| **Codex の端末識別子（installation_id）** | Codex が端末ごとに持つ識別子 |

加えて**Codex の動作ログに、呼び出し先（chatgpt.com）が返す応答のクッキーが 1 行残る**
（ChatGPT のアカウントでのサインインで観測）。
この動作ログは**本システムが管理する一時領域**にあり、
**Codex の終了時と本システムの次回起動時に消える**。

- **送信履歴（AI へ何を送ったかの事後確認）に載るのは、本システムが Codex へ渡した内容**である。
  Codex が付け足した上の 3 つは送信履歴には含まれない（種類は本章と画面の注意喚起で示す）。
- **利用者ホームの skill の一覧（名前・説明・パス）と、作業フォルダ外の画像は送られない**。
  これは Codex App Server を採用する条件であり、送られないことを実機で確かめてある。

## 6. プランの残量の見かたと、残量が尽きたとき

**ChatGPT のアカウントでサインインしているときだけ**、設定画面と AI 利用量ダッシュボードに
**プランの残量**が参考として表示される。シークレットキー方式では表示されない（値が届かないため）。

- 表示するのは**枠ごとの使用率・枠の長さ・次の回復時刻**と、**その値を受け取った時刻**である。
  枠の本数と長さはプランによって違う（Free は 30 日で 1 枠だった = 実測）。
- **値は直近の AI 呼び出しのときに Codex から受け取ったもの**である。
  画面を開いても取りに行かない（**閲覧の操作で通信は起きない**）。まだ一度も受け取っていないときは
  「まだ取得していません（AI を使うと表示されます）」と出る。
- **残量はトークン上限の判定には使わない**。上限の判定は従来どおりトークン数で行う。

**残量が尽きたとき**、AI を呼ぶ操作は止まり、残量切れが理由であることと、取れる操作
（回復時刻まで待つ／設定画面で認証方式またはプロバイダを切り替える）が表示される。

> **本システムは認証方式・プロバイダを自動では切り替えない**。
> 切り替えると課金とデータ利用ポリシーが変わるため**担当者が手で切り替える**。

## 7. サインインだけに依存する運用にしない

**ChatGPT のアカウントでのサインインが後から制限・停止される可能性がある**。
本システムからのサインインは Codex 自身のクライアントとして認可されており、
他社製アプリから ChatGPT のプランの利用枠を使ってよいかを OpenAI の公式文書は明示していない。

そのため**次のどちらかを常に用意しておく**こと。

1. **シークレットキー方式のキーを持っておく**（Codex App Server のまま認証方式だけを切り替えられる）
2. **他のプロバイダ（Anthropic / OpenAI / Google の API）のキーを持っておく**（プロバイダごと切り替えられる）

サインインできない・拒否された場合は設定起因のエラーとして表示され、
**切り替えの案内が出る**。プロジェクトのデータは失われず、AI を呼ばない操作は続けられる。

また Codex は試験提供の段階にあり、版ごとに通信の取り決めや設定が変わる。そのため
**Codex の版は本システムの版ごとに 1 つに固定**してある。
**利用者の端末にインストールされている Codex は使わない**ので、端末側で Codex をインストール・更新する必要はない。
端末に別の版の Codex がインストールされていても、本システムは同梱した版を使う。

## 8. 回答モード（ステークホルダー）でも選べる

回答モードの**任意の AI 対話回答**でも、AIプロバイダとして Codex App Server を選べる
（認証方式は 2 つとも）。

- **AI なしの構造化回答 UI だけで回答を完了できる**ことは変わらない（AI 対話回答は任意機能）。
- **担当者はキーを渡さない・サインインを代行しない**。ステークホルダー自身のシークレットキー、
  または自身の ChatGPT のアカウントでのみ使う。
- 有効にする操作のときに、担当者モードと同じ注意喚起（3 章・5 章の内容）が表示される。
- **回答モードではプランの残量を表示しない**。残量が尽きたときは
  「この操作は現在使えません。システム担当者へ連絡してください。」と表示される。
- サインインした場合は**回答の確定後にサインアウトできる**（その導線が画面に案内される）。

## 9. 配布物が大きくなること・初回起動に数秒かかること

Codex 本体を配布物へ同梱しているため**取得するファイルが大きい**（2026-09-14 実測）。

| | 同梱前 | 現在 |
|---|---|---|
| 配布物（macOS の dmg） | 37.8MB | **215MB** |
| アプリ本体（`.app`） | 約 25MB | **444MB** |

- **自動更新で取得する量も同じだけ増える**。帯域やプロキシの制限がある社内ネットワークでは、
  取得に時間がかかることがある。
- **Codex App Server を使わない利用者も同じ量を取得する**（配布物は OS ごとに 1 個）。

**インストールの直後と、更新の直後の 1 回だけ、起動に数秒かかる**。

| 起動 | 実測（2026-09-14。macOS 26.6.2 / Apple Silicon） | 基準（本システムの目標値） |
|---|---|---|
| **初回**（インストール・更新の直後の 1 回） | **6.9 秒** | **15 秒以内** |
| **2 回目以降** | **0.3 秒** | **5 秒以内** |

理由は**OS がアプリ本体を初回起動時に走査する**ためである。
故障ではないので初回はそのまま待つ。2 回目以降は同梱前と変わらない。
